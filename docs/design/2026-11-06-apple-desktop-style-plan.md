# Invoice Hub 苹果桌面风格优化任务

日期：2026-11-06。改造前审查对象：`design/desktop-visual-polish` 工作树，包含上一轮尚未提交的界面优化。

目标是借鉴 macOS 桌面工具应用的侧栏、工具栏、列表、检查器和分组表单，让日常报销更清楚、更安静。保留当前 Windows 应用的原生窗口操作与键盘约定。下面的颜色、尺寸是本项目的设计建议值，不是对苹果规范的逐项引用。

## 实施结果

以下记录本轮实际落地的改动；后文保留改造前观察及原始任务清单，便于对照。

| 范围 | 已实施内容 |
| --- | --- |
| AP-01 | 邮箱账号区根据实际内容分配 56–140 逻辑像素高度；单账号完整显示，多账号滚动。长账号名省略显示，保留完整提示、可访问名称和原生空格键选择行为。 |
| AP-02–04、AP-13 | 统一中性表面、13px 正文、32px 常规控件和 28px 紧凑控件；UI kit 位于统一 QSS 的最后一层。侧栏、分段筛选、菜单和详情按钮采用稳定的焦点边框，修复旧样式最小高度大于最大高度造成的裁切。SVG 图标提供深浅色和控件状态变体。 |

| AP-08 | 工作台减少重复计数和同权重卡片，保留继续审核入口；没有真实导入活动时隐藏活动卡片，零值使用中性文字。 |

| AP-10–11 | 导入来源改为紧凑分段选择；设置导航显示常用/高级分组，保留原页面索引及路由，子页统一内边距。 |
| AP-12、AP-14 | 空状态突出第一次导入，后两步降为简短指引；真正无记录时隐藏搜索，筛选无匹配时保留恢复入口。审核摘要只出现在审核页，避免跨页遗留滚动提示。 |
| AP-15 | 已完成本地真实 Qt 窗口截图、键盘与布局回归、深浅色实际文字对比度，以及同机五组性能对比。实体 Windows 的系统字体、标题栏、100%/125%/150% DPI、读屏和高对比度仍需原生环境验收。 |
| AP-16 | 审核反馈缩短至 150ms；减少动态效果开启时停止旧动画并保持不透明。使用实色表面，本轮没有加入背景模糊。 |

同时修复了两个交互边界：审核快捷键限定在审核工作区，避免抢占筛选卡片的回车键；列表销毁后的延迟刷新先检查 Qt 对象是否仍有效。

### 本地验证与证据边界

- 使用隔离的合成数据库，截图覆盖六个主页面，以及连续审核、购买方异常、导出阻断、深色和紧凑空状态。窗口尺寸覆盖 1150×850、1366×768、1440×900、1920×1080；另有 1150×600 空状态检查。
- Qt 离屏缩放分别检查 1、1.25、1.5。它们用于发现本地布局问题，不替代实体 Windows DPI 验收。原生截图工具的离屏拒绝保护保持有效。
- 59 个相关模块共 297 项测试通过（不重复计算补跑与 subtests），覆盖导入账号选择、布局几何、键盘焦点、分页、预览、导出阻断、设置路由、主题、启动及清理。完整 HCI 的 19 个场景通过，未留下线程或应用进程。编译、CLI、架构、隐私与发布元数据门禁通过，`git diff --check` 干净。
- 性能基准为 `2ea2ac0fb974111abf72a7a1d190fb0137e5a12a`，同机串行交替采样前后各五次。中位数：GUI 导入至首绘 2140→2109ms，50→100 条分页 115→126ms，切换并绘制 200 张发票导出清单 257→166ms。分页增加约 11ms，保留这一差异，不把它描述成全面提速。
- 性能测量使用 Linux offscreen 和预热的系统缓存，排除 QApplication 创建及合成数据准备；不代表 Windows 安装包冷启动指标。
- 截图、逐模块日志和性能原始样本位于本次会话的 `apple-desktop-implementation-20261106` 产物目录。源码改造留在 `design/desktop-visual-polish` 工作树，待按用户后续指令提交。

## 改造前审查依据

重新启动真实 PySide6 窗口，使用隔离的合成数据库，采集并逐张查看六个页面。截图与几何记录保存在本次审查产物 `apple-style-audit-20261106`，截图浏览页与本任务清单一并交付。

| 步骤 | 页面 | 当前健康度 | 截图观察与改造重点 |
| --- | --- | --- | --- |
| 1 | 今日工作台 | 主要入口清楚，视觉仍偏重 | 任务数量在卡片、徽标、按钮和概况中重复；边框卡片较多；可减少重复信息，形成清楚的主次动作。 |
| 2 | 导入中心 | 存在可见的可用性问题，先修复 | 邮箱账号行被裁切；来源选择占据一整张大卡片；工作区出现与其他页面不同的大面积灰底。 |
| 3 | 发票审核 | 核心流程可用，组织方式可继续统一 | 顶部搜索被包在大白卡中；表格每行都有彩色胶囊；摘要、详情、材料和预览仍有较多嵌套边框；票面工具条以文字操作为主。 |
| 4 | 报销组与导出 | 三列已对齐，浏览效率仍可改善 | 组内发票是多字段拼接的一行文本；正常检查项占据大部分检查区；报销组工具条又嵌在一层边框里。 |
| 5 | 系统设置 | 信息可读，分组与层级有偏差 | 全局侧栏之外还有设置侧栏；右侧子页标题贴近分界线；说明提到常用/高级，但当前分类没有显示对应分组。 |
| 6 | 首次使用空状态 | 操作入口齐全，视觉主次不足 | 三步卡片具有相近的视觉权重；没有发票时仍展示审核搜索；下半屏是大面积白色外壳。 |

导入中心的裁切在额外等待两秒后仍然存在：账号内容需要 40 逻辑像素，滚动视口只有 16；复选框在视口中的纵向范围为 9–30，无法完整显示。这是本次离屏环境中实测到的布局问题。具体成因需在修复时结合布局约束定位，不把尚未验证的根因写成结论。

截图可以支持布局、内容层级与可见状态的判断。真实邮箱运行、Windows 窗口装饰、系统字体、读屏、系统高对比度和实体 DPI 不属于这次已完成的验证。

## 拟采用的视觉基线

| 项目 | 建议 |
| --- | --- |
| 背景与层级 | 浅中性页面背景、略深侧栏、白色工作内容；用间距和细分隔线组织层级；保留确有分组意义的卡片。 |
| 候选颜色 | 页面 `#F5F5F7`、侧栏 `#EFEFF2`、内容 `#FFFFFF`、主文字 `#1D1D1F`、次文字 `#63636A`、强调色 `#0066CC`。通过对比度检查后再落地，统一从设计 token 输出。 |
| 颜色用途 | 蓝色用于主要操作、链接和焦点；成功、警告、错误保留语义颜色与文字/图标。正常资料状态采用安静的文字或小图标。 |
| 文字层级 | 页标题约 20–22，分组标题 14–15，正文 13–14，辅助文字约 12 逻辑像素；常规正文使用普通字重，标题适量加粗；金额使用对齐的数字。 |
| 控件密度 | 常规按钮和输入框约 32，紧凑工具条约 28，图标命中区域至少 24；表格保持适合财务审核的密度，不整体放大成移动端控件。 |
| 字体与图标 | 按平台选系统字体，Windows 中文回退到微软雅黑；继续使用项目 SVG 图标，统一线宽、尺寸和状态色，不引入额外字体包或 SF Symbols 依赖。 |
| 分段控件 | 中性轨道、清楚的选中面、稳定的键盘焦点；不把五个状态分别渲染成五种彩色卡片。 |
| 材质 | 第一版采用清晰的实色表面；模糊与半透明只作为后续可选增强，正文和票据原件保持清楚。 |

## 建议执行顺序

1. **先修可用性**：AP-01；同时为账号行完整显示补有意义的几何与交互验证。
2. **统一基础组件**：AP-02 → AP-03 → AP-04 → AP-13。先让侧栏、文字、按钮、图标和状态一致，再迁移具体页面。
3. **完成报销主路径**：AP-05 → AP-06 → AP-07 → AP-08 → AP-09 → AP-10 → AP-11。每个页面用相同数据和尺寸做前后对照。
4. **整理辅助体验**：AP-12 → AP-14，完成首次使用、无匹配、失败恢复和日常反馈。
5. **收口验证**：AP-15 在每批执行相关检查，最后完整运行 HCI 和原生 Windows 验证；AP-16 根据前四批效果与性能决定是否纳入。

## 实施与验收约束

- 修改现有标准组件和布局入口，不新增另一层 `*_fixes.py` 或整页覆盖样式。
- 表格滚动位置、已选票据、审核状态、报销组、未保存编辑、材料绑定和导出范围必须在样式迁移后保持一致。
- 本轮审查沿用上一轮工作树；没有把上一轮的本地测试结果充当苹果风格改造已经通过的证据。实施后必须重新验证。
- 小字与控件边界需检查实际对比度；不为追求浅灰外观而降低可读性。警告、错误与选中状态不只依赖颜色。
- 真实 Windows 的窗口装饰与系统行为单独验证；本轮 QWidget 截图不包含完整原生标题栏。
