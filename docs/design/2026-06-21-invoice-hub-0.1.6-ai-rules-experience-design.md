# Invoice Hub 0.1.6 AI、规则与体验收尾设计

## 目标

在 0.1.5 设置中心框架上，把已有 AI profile、本地关键词分类、分类字典、运行状态和安全边界统一呈现，使用户能够明确知道当前启用了什么、密钥是否可用、哪些数据会发送给云端、失败后如何降级，以及本地规则与 AI 的实际分工。

0.1.6 不建设通用规则引擎、训练平台或任意模型路由，而是把真实能力做清楚、可管理、可诊断。

## 产品原则

1. 默认关闭 AI 时，产品仍完整使用本地规则、白名单和人工审核。
2. 最多启用一个 AI profile；其他 profile 可以保存但不并行运行。
3. 只支持现有 DeepSeek 和 Gemini provider，不展示虚假的插件化入口。
4. AI 只接收掩码后的邮件主题与发件人，不发送正文、附件、PDF 或本地文件。
5. 固定关键词规则是只读系统能力，不伪装成可视化脚本编辑器。
6. `categories` 分类字典可以管理显示值，但不等于分类条件或规则 DSL。
7. 认证或调用失败时保持待分类，不覆盖已有本地规则结果。

## 方案选择

- 方案 A：建设完整规则编辑器和多模型平台。扩展性高，但当前没有执行后端，拒绝采用。
- 方案 B：在统一设置中心中管理 AI profile、只读展示固定规则、管理分类字典。与现有能力一致，采用此方案。
- 方案 C：只保留现有表单，不增加规则与安全说明。改动最小，但用户无法理解 AI 边界和失败降级。

## 版本边界

### 包含

- AI 配置列表、空状态、启用、停用、编辑和删除。
- AI 三步配置向导。
- API Key 来源和安全状态。
- 用户主动触发的配置验证。
- 本地规则概览、规则来源和 AI 兜底流程说明。
- 分类字典管理，仅覆盖现有 `categories` 能力。
- AI 运行状态、暂停、失败和待分类反馈。
- 全局空、加载、错误、禁用、确认、撤销和可访问性收尾。

### 不包含

- 任意条件编排、脚本、正则或规则 DSL 编辑器。
- 修改代码常量中的本地关键词和技术通知排除规则。
- 多模型并行、自动路由、负载均衡或成本优化平台。
- 模型训练、微调、标注回流和自动学习。
- 任意第三方 provider 接入。
- 云端读取邮件正文、附件或发票文件。
- 规则在线同步、团队共享和权限审批。

## 信息架构

0.1.6 在 `SettingsLayout` 中正式开放：

```text
AI 配置
分类与规则
运行状态
安全与隐私
```

邮箱账户、系统设置、数据与备份和关于继续沿用 0.1.5，不改变其身份和保存语义。

## AI 配置页

### 页面结构

```text
页面标题 + 当前能力说明                    新增 AI 配置
状态摘要：AI 状态 / 当前配置 / 密钥状态 / 最近校验
配置列表
云端数据边界说明
```

摘要使用一行紧凑状态，不使用大型仪表盘。

### AI 配置行

每个 `AIConfigRow` 显示：

- 配置名称。
- provider 与模型。
- 状态：当前启用、已保存未启用、缺少密钥、待验证、验证失败。
- Key 来源：配置专用、provider 旧 Key、环境变量、未配置。
- 最近校验时间；无真实记录时显示“尚未校验”。
- 主要动作：启用或编辑。
- 次要菜单：验证、停用、删除。

Key 来源只显示枚举，不显示 Key 片段、长度或可推断内容。

### 空状态

AI 未配置时显示“AI 当前关闭，本地规则仍会继续工作”，并提供“新增 AI 配置”。不得把 AI 关闭显示为系统错误。

### 启用与停用

- 启用前必须存在可用 Key 来源。
- 启用一个 profile 时原 active profile 自动停用，并在确认中明确说明切换对象。
- 停用 AI 保留所有 profiles 和系统凭据，只把运行投影改为 `provider=none`。
- 删除 active profile 前必须先确认，删除后 AI 关闭，不自动启用另一个 profile。

## AI 三步配置向导

使用 760×560 `WizardDialog`，延续 0.1.5 的步骤头和底栏。

### 第一步：基本信息

- 配置名称。
- provider：DeepSeek、Gemini。
- 模型：provider 默认值和可编辑模型名称。

`none` 不是新建 provider 选项；停用通过列表页动作完成。

### 第二步：模型与密钥

- 模型名称。
- `SecureInput` API Key。
- 当前 Key 来源和覆盖说明。
- 批次大小只在现有运行时真实支持且具有安全范围时显示；否则沿用系统默认，不提供无效控件。

保存新 Key 后只进入系统凭据存储。清空输入不删除旧 Key；删除 Key 必须使用独立确认动作。

### 第三步：复核与验证

显示配置名称、provider、模型、Key 来源和云端数据边界。

动作：

- 仅保存。
- 保存并设为当前。
- 验证配置。

配置验证分两层：

1. 本地验证：profile 字段、provider、模型和 Key 来源完整。
2. 用户主动触发的 provider 验证：使用固定的最小合成请求，不发送真实邮件或发票数据；明确提示可能产生少量 API 调用。若 provider adapter 无安全验证能力，则只完成本地验证并如实显示“未执行联网验证”。

验证成功不代表分类质量，只代表配置可调用。

## AI 状态机

| 状态 | 含义 | 主动作 |
|---|---|---|
| `disabled` | 无 active profile | 启用配置 |
| `saved` | profile 已保存未启用 | 启用 / 编辑 |
| `missing-key` | 无可用 Key 来源 | 配置 Key |
| `unverified` | 字段有效但未联网验证 | 验证 / 启用 |
| `valid` | 最近验证成功 | 启用 / 编辑 |
| `invalid-auth` | 认证失败 | 更新 Key / 重试 |
| `request-failed` | 网络或 provider 调用失败 | 重试 / 保持关闭 |
| `session-paused` | 当前扫描会话已暂停 provider | 查看原因 / 下次扫描重试 |

`session-paused` 是运行态，不永久修改 profile。错误恢复后不得自动覆盖人工选择的 active profile。

## 分类与规则页

### 分类流程说明

页面顶部固定显示真实顺序：

```text
本地关键词与技术通知排除
        ↓ 不确定
可信发件人/既有业务判断
        ↓ 仍不确定且 AI 已启用
AI 仅判断掩码后的邮件头
        ↓ 失败
保持待分类，交由人工处理
```

### 本地规则概览

使用只读 `RuleSection` 展示：

- 发票正向关键词规则：启用、系统内置、只读。
- 排除关键词规则：启用、系统内置、只读。
- 技术通知排除：启用、系统内置、只读。
- 冲突处理：正向与排除同时命中时转为不确定。

只展示规则类型、作用、状态和示例数量，不默认展开完整关键词常量。可以查看说明，但不能编辑、删除或停用代码规则。

### 分类字典

分类字典只管理可选分类名称：

- 显示内置分类、配置分类和数据库历史分类的来源。
- 允许新增或重命名配置分类。
- 删除前检查是否仍被发票使用；已使用分类不能直接消失，只能停止推荐。
- 字典变化不重跑历史分类，也不创建邮件识别条件。

页面必须明确提示：“分类名称不是识别规则”。

### AI 兜底策略

显示当前 active profile、AI 开关、Key 状态和失败降级。用户可以跳转 AI 配置，不在规则页重复编辑 Key 或模型。

## 运行状态页

只展示真实可追溯状态：

- AI 启用/关闭。
- 当前 active profile。
- 当前会话是否暂停。
- 最近一次认证或请求错误摘要。
- 待分类数量。
- 最近一次扫描中的 AI 待处理数量，仅在真实扫描结果提供时显示。

不展示虚构的准确率、成本、令牌、趋势图或历史成功率。没有持久化历史时，只显示当前会话和最近结果。

## 安全与隐私页

必须明确区分：

| 会发送给 AI | 不会发送给 AI |
|---|---|
| 掩码后的主题 | 邮件正文 |
| 掩码后的发件人 | 附件、PDF、图片 |
| 最小分类请求元数据 | 本地文件路径 |
| | 邮箱授权码、API Key |

同时说明：

- API Key 存储于系统凭据管理器。
- 配置文件和日志会剥离 secret。
- provider 调用失败时数据保持待分类。
- 删除 profile 可选择是否同时删除其系统凭据；默认不静默删除。

## 全局体验收尾

### 通用状态

所有主要页面统一使用 `StatePanel`：加载、空、错误、禁用、无结果。所有保存、测试、扫描和删除动作必须有 busy 状态，避免重复提交。

### 反馈层级

- Toast：保存成功、启停成功、复制非敏感信息。
- 页面错误：连接失败、认证失败、字段错误、无结果。
- 确认对话框：删除、替换 active profile、丢弃未保存修改。
- 撤销：只用于可安全恢复的分类字典停用等操作，不用于密钥或配置删除。

### 文案

错误必须说明：发生了什么、当前数据是否保留、下一步能做什么。不得直接显示 provider 原始响应、请求 URL、secret 或堆栈。

## 组件复用与新增

复用 0.1.4/0.1.5：`SettingsLayout`、`ConfigListRow`、`WizardDialog`、`SecureInput`、`SafetyNotice`、`SectionCard`、`StatusBadge`、`StatePanel`、`ToastHost`。

0.1.6 只新增组合组件：

| 组件 | 组成 | 边界 |
|---|---|---|
| `AIConfigRow` | `ConfigListRow` + Key/active 状态 | 不读取 Key 明文 |
| `RuleSection` | `SectionCard` + 只读规则摘要 | 不执行或修改规则 |
| `ClassificationDictionary` | 紧凑列表 + 来源徽章 | 只管理名称，不管理条件 |
| `RuntimeStatusPanel` | `StatePanel` + 最近真实状态 | 不生成统计数据 |

## 键盘与可访问性

- 设置中心延续 0.1.5 Tab 顺序和 `Esc` 未保存保护。
- 列表主要动作可通过 Enter 触发，菜单通过标准键盘菜单导航。
- Secret 控件可粘贴但不可复制或剪切。
- 状态具有文字，不只依赖颜色。
- 125% 和 150% 缩放、高对比度模式下主要操作和错误文案完整可见。
- AI 验证和删除等长操作不能锁死窗口，完成后焦点回到触发控件或结果区。

## 响应式规则

- 1920×1080：1120×720 设置中心完整展示，配置列表至少可见 6 行。
- 1440×900：导航压缩，列表仍显示名称、provider、模型、状态和主动作。
- 1366×768：导航折叠，辅助安全说明折叠，配置行允许次信息省略；关键动作始终可达。
- 所有尺寸不得使用横向滚动解决主布局问题。

## 验收标准

1. AI 关闭时本地规则和人工审核继续正常工作，不显示系统错误。
2. 最多一个 active profile；启用、停用、删除和 legacy 投影保持一致。
3. Key 来源只显示枚举状态，Key 不出现在配置、界面、日志或错误中。
4. Provider 验证不使用真实邮件、附件或发票数据，并明确联网验证是否实际执行。
5. 固定本地关键词规则只读展示，不出现虚假的条件编辑器或启停能力。
6. 分类字典管理不会被描述或实现为识别规则，也不会静默改写历史发票。
7. AI 认证、网络或响应失败时保持待分类，不污染本地规则结果。
8. 运行状态页只展示真实数据，不出现虚构准确率、成本或趋势。
9. 1920×1080、1440×900 和 1366×768 均可完成 AI 配置、启停、验证和分类字典管理。
10. 所有空、加载、错误、禁用、确认和未保存状态具有一致反馈和键盘路径。
