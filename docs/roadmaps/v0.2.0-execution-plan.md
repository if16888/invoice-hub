# v0.2.0 开发执行计划

基于 `v0.2.0-unified-roadmap.md` 的 P0 → P1 → P2 顺序实施。
本文件记录审查后的实施约束；与原规划中的示例冲突时，以本文件为准。
开发在 `feat/v0.2.0` 进行，v0.1.8 发布基线保持不变。

## 本次新增需求：单票快捷归组

- `Ctrl+G`：在发票审核页，将当前选中行加入详情区所选的报销组。
- 即使表格多选，也只处理当前行；原“加入”按钮保留批量行为。
- 无当前选中行或无目标组时给出提示。禁止将已归其他组的票据直接转组。
- 输入框与模态窗口内不执行，其他页面不操作隐藏的审核记录。
- 成功通过状态栏反馈，不弹结果确认框；刷新后保持当前发票，防止连按误加下一张。
- 快捷键说明与加入按钮提示同步展示。

实现与专项回归已添加；最终 Windows 键盘与 DPI 验收随 v0.2.0 验收进行。

## P0：数据与财务交付

1. 先完成事由模型及可重复执行的迁移，再连通报销组编辑、单票覆盖与导出。
   老数据事由保持空值，不默认标记“差旅”；继承值与单票覆盖值分别保存。
2. 税号保留未知/未采集状态；按证件类型校验，不对全部票据强制 18 位。
   税额使用 Decimal；允许免税、多税率、缺失数据及明确的舍入误差规则。
3. 无票号疑似重复作为独立复核标记，不增加或覆盖现有审核状态，
   不以票号长度猜测是否有效；允许同商家同日同金额的真实多笔。
4. 导出封面、事由列及安全文件名，保持静态 Decimal 汇总。
   openpyxl 不能通过赋值公式同时写入可靠缓存，不采用原稿的“双重写”。
5. 分开安排证明材料共享迁移，覆盖旧 extra_paths、软删除、解绑与备份恢复；
   不把所有尚未完成的功能字段塞进一个无法独立验收的迁移。

## P1：审核与导入体验

- 在现有 QSplitter 与组件目录上调整布局，不新建平行 src/gui 架构。
- 批量操作明确区分已加载记录与完整筛选结果，并在提交前复核异常。
- 商户分类记忆、材料共享、拖拽、财务编辑字段按各自业务契约逐项实现。
- 网络诊断放在电脑侧可达入口；手机页不能诊断页面自身无法加载的问题。
- 单票归组快捷键已作为首个独立交付项提前实施。

## P2：状态与交付治理

- 导出与已报销分开，状态转换显式确认并保存审计记录。
- Manifest 对实际导出文件计算 SHA-256；覆盖缺文件和校验失败路径。
- 分阶段降低历史补丁依赖，不禁止必要修复；性能数字以实测报告为准。
- 保留实体 Windows 安装、升级、重启、DPI、手机与邮箱验收门槛。
