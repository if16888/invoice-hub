# 多邮箱与多 AI 配置中心设计

日期：2026-06-19

## 目标

- 点击“系统配置”后先展示邮箱账号和 AI 模型配置列表。
- 邮箱和 AI 配置均支持新增、查看、编辑、删除。
- 新增与编辑沿用分步向导，保存后返回原列表。
- 多个邮箱可以同时启用；AI 配置可以保存多个，但最多一个生效。
- 没有生效的 AI 配置时，AI 自动视为未启用，不设置独立总开关。
- 保留现有配置和系统凭据，升级后无需用户重新录入。

## 非目标

- 不实现 Outlook OAuth2。
- 不实现多个 AI 模型的自动故障转移、优先级或并行调用。
- 不增加邮箱批量操作。
- 不修改发票导入、审核、分类和导出主流程的业务规则。

## 信息架构

系统配置窗口固定以“配置中心”列表为首页，使用两个页签：

1. `邮箱账号 N`
2. `AI 模型 N`

窗口记住当前页签。新增或编辑完成后返回来源页签，并尽量恢复列表滚动位置。

### 邮箱列表

每项展示：

- 配置名称
- 脱敏邮箱地址
- 邮箱服务商
- 扫描月份范围
- 启用状态
- 凭据或最近测试状态
- 操作：启用/停用、编辑、删除

没有邮箱时展示空状态和“新增邮箱账号”主按钮。多个邮箱可以同时启用。

### AI 列表

每项展示：

- 配置名称
- 服务商
- 模型名称
- API Key 是否已安全保存
- 是否为当前生效配置
- 操作：设为当前/停用、编辑、删除

AI 顶部状态由列表派生：

- 没有生效配置：`AI 功能未启用`
- 有一个生效配置：`AI 功能已启用：<配置名称>`

“AI 功能未启用”只是状态提示，不是独立开关。点击某项“设为当前”即启用 AI；点击当前项“停用 AI”即清除生效项。最多允许一个生效配置。

## 邮箱向导

新增和编辑复用同一向导：

1. 选择邮箱类型并填写配置名称、扫描月份范围。
2. 填写邮箱地址、授权码；自定义 IMAP 可展开服务器和端口。
3. 查看摘要、测试连接并保存。

新增使用空表单。编辑按账号 ID 加载配置，不再通过服务商卡片隐式选择同类邮箱。

邮箱地址、服务商、IMAP 服务器或端口变化后，连接测试状态失效。仅修改配置名称、启用状态或扫描月份时不强制重新测试。未测试成功仍可在二次确认后保存，沿用当前行为。

删除从列表发起并二次确认。删除邮箱配置、授权码和扫描同步状态，不删除已导入发票、本地附件或报销组。

## AI 向导

新增和编辑复用同一向导：

1. 选择真实 AI 服务商并填写配置名称。
2. 选择或填写模型名称、录入 API Key。
3. 验证配置并选择保存动作。

服务商只包含 `DeepSeek` 和 `Gemini`，不出现“暂不使用 AI”。第三步提供：

- `仅保存配置`
- `保存并设为当前`

已有当前配置时，“保存并设为当前”需要确认替换。编辑当前配置并保存后仍保持当前状态。编辑非当前配置不会改变生效项。

删除当前配置后 AI 直接关闭，不自动切换备用配置。删除非当前配置不影响运行状态。

## 配置模型

### 邮箱

继续使用现有 `email_accounts[]`。每项补齐稳定的 `mailbox_key` 作为编辑和删除标识，不以列表位置或服务商作为身份。

顶层 `email`、`imap` 和 `search` 继续映射到首个启用邮箱，保持现有 CLI 和旧配置兼容。

### AI

增加 `ai_profiles[]`：

```json
{
  "ai_profiles": [
    {
      "profile_id": "ai-7f2c19a4",
      "name": "发票分类主模型",
      "provider": "deepseek",
      "model": "deepseek-v4-flash",
      "enabled": true
    },
    {
      "profile_id": "ai-a8360d51",
      "name": "Gemini 备用",
      "provider": "gemini",
      "model": "gemini-2.5-flash",
      "enabled": false
    }
  ]
}
```

约束：

- `profile_id` 创建后保持稳定。
- 最多一个 `enabled: true`。
- `provider` 仅允许 `deepseek` 或 `gemini`。
- `name` 和 `model` 不能为空。

现有顶层 `ai` 继续作为运行时投影：

- 有启用配置时，写入其 `provider`、`model`、`profile_id` 和现有 `batch_size`。
- 无启用配置时，写入 `provider: "none"`、空模型，并保留 `batch_size`。

旧配置只有顶层 `ai` 时，在加载设置页时生成一个兼容配置：已启用服务商迁移为一项启用的 `ai_profiles`；`provider: "none"` 不生成配置。保存设置后再持久化新结构。

## 凭据存储

邮箱授权码继续按邮箱地址存储在系统凭据管理器。

AI API Key 改为按 `profile_id` 存储，使同一服务商的多个配置可以使用不同 Key。读取顺序：

1. 新的 profile 级凭据。
2. 旧的 provider 级凭据。
3. 对应环境变量。

旧凭据只读取不删除。用户编辑并保存 API Key 后写入 profile 级凭据。删除 AI 配置时仅删除该 profile 的凭据，不影响同服务商的其他配置或旧版回退凭据。

日志和界面只显示“已保存/未保存”，不得回显 Key 内容。

## 组件边界

`SettingsDialog` 保持外部入口不变，内部拆分为：

- 配置中心首页：页签、列表、空状态和 CRUD 路由。
- 邮箱编辑器：现有三步向导及连接测试。
- AI 编辑器：三步向导及凭据验证。
- 配置适配函数：列表归一化、旧结构迁移、当前配置投影。
- 凭据适配函数：profile 级 AI Key 读写和旧格式回退。

列表组件只传递稳定 ID，不直接修改配置字典。保存、删除和启用操作由对话框方法统一执行并刷新列表。

## 错误与确认

- 删除邮箱：说明不会删除已导入发票和附件。
- 删除当前 AI：说明删除后 AI 将关闭。
- 切换当前 AI：说明原当前模型将停用。
- AI Key 缺失或验证失败：允许“仅保存配置”，但不能“保存并设为当前”。
- 最后一个启用邮箱不可直接停用或删除；必须先启用另一个邮箱，避免扫描配置进入无可用账号状态。
- 配置文件或凭据写入失败：保持窗口打开，不更新父窗口配置，显示脱敏错误信息。

## 测试范围

### 配置与兼容

- 旧单邮箱配置迁移后仍可加载和保存。
- 多邮箱的新增、编辑、启用、停用和删除不影响其他账号。
- 旧 `ai` 配置生成兼容 profile。
- 零个 AI 生效项投影为 `provider: none`。
- 多个 AI 生效项被校验拒绝或确定性归一化为一个，并给出明确诊断。

### 凭据

- 同服务商不同 profile 的 Key 相互隔离。
- profile 凭据缺失时可读取旧 provider 凭据和环境变量。
- 删除一个 profile 不删除其他 profile 的 Key。
- 所有错误和日志不泄露邮箱授权码或 AI Key。

### 界面

- 打开系统配置先显示列表首页。
- 页签数量、空状态和当前 AI 状态正确。
- 新增与编辑加载正确对象，保存后返回来源页签。
- AI “设为当前”和“停用 AI”状态切换正确。
- 删除确认文案和取消路径正确。
- 现有 Outlook 不支持提示、邮箱连接测试和高级 IMAP 行为保持不变。
