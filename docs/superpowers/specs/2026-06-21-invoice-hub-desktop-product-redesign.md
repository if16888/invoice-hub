# Invoice Hub 0.1.4–0.1.6 桌面端产品重构设计

## 目标

把 Invoice Hub 从功能分散的桌面工具重构为适合办公人员长期高频使用的发票审核中心。设计优先保证审核路径短、信息集中、状态一致和后续功能可扩展，不追求一次性重做全部页面。

本设计以用户提供的参考图为视觉目标，以现有 PySide6 桌面应用为实现边界。参考图用于确定信息层级、密度、颜色和交互方向，不表示主工作台、设置中心与多个弹窗需要同时出现在一个实际窗口中。

## 已确定的产品原则

1. 审核工作台是产品主入口，高频审核优先于低频配置。
2. 默认按 1920×1080 桌面办公尺寸设计，同时保证 1440×900 和 1366×768 可用。
3. 主窗口保持单页三栏工作流，尽量不通过额外弹窗完成审核。
4. 通用组件从 0.1.4 开始建设，后续版本复用，不为假想需求过度抽象。
5. 每个版本形成独立可验收闭环，不把未完成页面作为空壳加入导航。
6. 保留现有导入、解析、去重、筛选、预览、报销、导出、邮箱身份和密钥隐私语义。
7. 继续使用 PySide6、QSS、语义属性和回调模式，不引入 Web UI 技术栈。

## 版本边界

### 0.1.4：审核工作台与通用组件基础

交付：

- 统一应用框架、左侧导航和顶部工具栏。
- 发票状态统计、列表、预览、审核详情三栏工作台。
- 更容易编辑的备注和更紧凑的报销组区域。
- 扫码上传横向弹窗与完整服务状态。
- 第一批通用组件、设计 Token、反馈状态和键盘操作。
- 保持现有导入、筛选、审核、附件、报销和导出能力可用。

0.1.4 只建设应用壳层和工作台实际使用的最小通用基建，不提前建设 `SettingsLayout`、`ConfigListRow`、`WizardDialog`、`SecureInput` 或 `SafetyNotice`。

不包含：

- 新的规则编辑器。
- 完整 AI 功能中心。
- 邮箱账户管理重构和新的授权向导。
- 数据备份重构、深色模式和复杂动画。

### 0.1.5：设置中心与邮箱闭环

交付：

- 统一设置中心框架。
- 邮箱账户列表、空状态、快捷同步设置。
- 邮箱接入三步向导。
- 授权码安全状态、连接测试和同步预览。
- 设置类通用组件。

不包含：

- Outlook OAuth2 的新业务实现；仍明确提示并保持现有阻断语义。
- 复杂邮件识别规则编辑器。
- 邮箱服务端管理平台或远程凭据同步。

### 0.1.6：AI、规则与体验收尾

交付：

- AI 配置中心、配置状态、连接测试和默认模型管理。
- 基于现有规则能力的规则汇总、启停和现有阈值字段编辑；不增加新规则类型或表达式能力。
- 加载、错误、禁用、确认、撤销和帮助文案统一。
- 全局键盘操作、可访问性和小尺寸窗口打磨。

不包含：

- 新建工作流引擎。
- 云端账号系统。
- 多用户权限、审批流和在线协作。

### 排版与尺寸

- 字体：`Segoe UI`，中文回退 `Microsoft YaHei UI`。
- 正文：13 px；辅助文字：12 px；强调文字：14 px；区块标题：16 px；金额：20 px。
- 间距采用 4、8、12、16、20、24、32 px 序列。
- 紧凑控件高度 32 px，标准控件 36 px，主要操作 40 px。
- 控件圆角 6 px，卡片 8 px，对话框 10 px。
- 阴影仅用于浮层、菜单和对话框，普通卡片使用边框区分。
- 表格默认行高 40 px，允许紧凑模式 36 px。

### 图标

- 所有组件通过 `QIcon` 接收图标，不在组件内部硬编码文本符号或 emoji。
- 0.1.4 优先复用仓库现有图标和 Qt 标准图标。
- 0.1.4–0.1.6 不新增第三方图标集；新增图标只使用仓库现有资源或 Qt 标准图标。
- 关键操作必须保留文字标签，不能只依赖图标。

## 通用组件体系

通用组件必须满足以下任一条件：被至少两个页面使用，或具有长期稳定的交互语义。数据库查询、配置读写和业务判断不得进入通用组件。

### 0.1.4 基础组件

| 组件 | 职责 | 稳定接口 |
|---|---|---|
| `AppShell` | 组合导航、顶部栏、内容区和全局反馈层 | 当前路由、内容 Widget、导航折叠状态 |
| `SideNav` | 展示当前版本可用入口 | 导航项列表、当前项、`route_requested` |
| `TopToolbar` | 全局搜索和高频动作 | 搜索文本、动作列表、忙碌状态 |
| `PageHeader` | 页面标题、说明和页面级动作 | 标题、说明、动作列表 |
| `ActionButton` | 统一按钮尺寸与状态 | `variant`、`size`、`busy`、`enabled` |
| `StatusBadge` | 映射业务状态到统一视觉 | 状态代码、显示文字、辅助说明 |
| `StatCard` | 展示数量并触发筛选 | 标题、数值、状态、是否选中 |
| `SectionCard` | 统一面板标题、边框和内边距 | 标题、操作区、内容 Widget |
| `FilterBar` | 组合快速筛选和高级筛选入口 | 筛选项、当前条件、重置动作 |
| `DataTable` | 统一表头、行高、选择与筛选标记视觉 | 现有表格语义、列定义、选择状态 |
| `StatePanel` | 展示空、加载、错误、禁用状态 | 模式、标题、说明、主动作、次动作 |
| `DialogShell` | 统一标题区、内容区和底部动作 | 标题、尺寸、主次动作、关闭策略 |
| `ToastHost` | 展示短时操作反馈 | 级别、消息、持续时间、恢复动作 |

`DataTable` 在 0.1.4 中对现有 `QTableWidget` 做视觉和状态封装，不更换数据模型，不重写已经稳定的列筛选语义。

组件嵌套规则：

- `SectionCard` 只负责外层标题、边框、内容和可选动作区。
- `DataTable` 只呈现表格，不自行创建空态、错误态或外层卡片。
- 页面使用 `QStackedWidget` 在 `DataTable` 与 `StatePanel` 之间切换，两者不互相嵌套。
- `StatePanel` 的主动作固定在前，次动作固定在后；重试、清除筛选和返回等恢复动作沿用这一位置规则。

0.1.4 的组件建设顺序固定为：设计 Token与现有组件工厂扩展、`ActionButton`/`StatusBadge`、`StatePanel`/`ToastHost`、`DialogShell`、`AppShell`/`SideNav`/`TopToolbar`，最后才是工作台需要的 `DataTable`、`StatCard` 和 `FilterBar`。业务组件只有在第二个页面出现相同语义时才提升为通用组件。

### 0.1.5 设置组件

| 组件 | 职责 |
|---|---|
| `SettingsLayout` | 设置导航、内容区和固定底栏 |
| `ConfigListRow` | 邮箱或 AI 配置的紧凑列表行 |
| `WizardDialog` | 三步配置流程、步骤状态和底部动作 |
| `SecureInput` | 密钥显示/隐藏、安全状态和本地存储说明 |
| `SafetyNotice` | 安全、隐私和不可逆操作说明 |

### 0.1.6 复合组件

- `AIConfigCard` 基于 `ConfigListRow`、`StatusBadge` 和 `ActionButton` 组合。
- `RuleSection` 基于 `SectionCard`、`DataTable` 和 `StatePanel` 组合。
- 复合组件可以读取页面传入的 view state，但不能直接读写数据库或凭据。

## 0.1.4 主工作台设计

### 窗口框架

主设计基准为 1920×1080，最小可用尺寸为 1280×720。应用在 1920×1080 屏幕上默认以最大化窗口启动，不强制进入全屏模式，保留 Windows 任务栏和系统窗口控制。

| 区域 | 默认尺寸 |
|---|---:|
| 左侧导航 | 208 px |
| 折叠导航 | 56 px |
| 顶部工具栏 | 60 px 高 |
| 页面内容边距 | 20 px |
| 发票列表 | 360–400 px |
| 发票预览 | 自适应，最小 720 px |
| 审核详情 | 420–460 px |

1920×1080 下三栏使用完整密度，不主动折叠任何核心区域。兼容尺寸按以下顺序降级：

1. 1440×900：导航保持展开或由用户折叠，列表压缩到 320–340 px，详情压缩到 360–400 px，预览保持不低于 560 px。
2. 1366×768：导航默认折叠为 56 px，列表压缩到 300–320 px，详情压缩到 340–360 px，垂直间距从 12–16 px 降为 8–12 px。
3. 1280×720：允许用户手动收起预览区，只保留列表和审核详情；该尺寸仅保证功能可用，不作为视觉验收基准。

任何兼容尺寸都不得通过主工作台横向滚动解决宽度不足。

### 顶部工具栏

左侧为全局搜索，支持发票号、销售方、购买方、金额和邮件主题。右侧按稳定顺序显示：导入发票、扫码上传、邮箱同步、批量导出、更多。

帮助、通知和账号只在存在实际功能时显示。低频动作进入“更多”，避免参考图在较窄窗口中出现按钮堆积。

### 状态统计

展示全部、待审核、已通过、已忽略、异常五个 `StatCard`。点击卡片立即更新列表条件，当前卡片显示选中态。统计数字和列表结果来自同一次数据刷新，不允许数字与列表条件不同步。

### 发票列表

固定展示：状态、费用日期、金额、销售方、发票号。

- 状态使用文字徽章或状态点加文字，不只显示颜色点。
- 金额右对齐，日期支持排序，长文本省略并提供 tooltip。
- 列筛选继续支持类别、销售方、发票号、日期和金额范围组合。
- 筛选后尽量保留当前选中发票；如果被筛掉，选择第一张可见发票。
- 列表底部展示当前筛选结果数量、选中数量和金额合计。
- 多选进入批量模式，详情面板不显示上一张发票的数据。

列表状态：

- 首次加载：骨架或“正在加载发票”。
- 数据为空：引导导入、扫码或邮箱同步。
- 筛选无结果：显示当前筛选摘要和“清除筛选”。
- 加载失败：保留筛选条件，提供重试。

### 发票预览

顶部工具栏固定展示：文档切换、缩放比例、缩小、放大、适合宽度、旋转、外部打开。“下载”和“打印”进入更多菜单，避免挤占主工具栏。

预览继续承担：PDF 页导航、图片/PDF 展示、原始文件与证据文件切换、外部打开和证据关联。工具栏动作必须根据文件类型显示禁用态和原因。

附件缩略图位于预览底部，当前附件有明确选中态。文件缺失时不显示空白画布，而是显示文件名、缺失原因和“重新定位/补充文件”动作。

### 审核详情

顶部摘要固定在详情滚动区之外：

```text
金额 + 发票类型 + 状态
费用日期 / 发票号
销售方 / 购买方
风险提示
通过并下一张 / 忽略 / 标记异常 / 更多
```

风险提示为空时不保留大块空白；出现风险时使用警告区块，但不推动主要操作按钮离开首屏。

详情内容使用三个 Tab：

1. 基本信息：日期、类型、金额、购买方、销售方、附件和来源信息。
2. 报销信息：费用分类、报销组、标签、备注和支持材料。
3. 操作记录：导入、编辑、审核、报销和导出历史。

关联合同不在 0.1.4 展示，直到存在真实合同数据和操作闭环。

### 保存与审核流程

字段修改后立即显示“已修改”，显式保存后显示“已保存”。

“通过并下一张”执行：

1. 校验当前可编辑字段。
2. 保存未保存修改。
3. 将当前发票标记为已通过。
4. 刷新统计、列表和详情状态。
5. 选择当前筛选结果中的下一张发票。

任何步骤失败时停留在当前发票，保留用户输入并显示可执行错误。忽略和标记异常使用相同事务边界，但标记异常必须要求异常原因。

### 备注

- 无备注时显示一行“添加备注”。
- 有备注时显示单行摘要，点击后在原位置展开为 3–4 行编辑器。
- `Ctrl+Enter` 保存，`Esc` 收起且保留未保存文本。
- 切换发票前存在未保存备注时，提示保存、放弃或取消切换。
- 不使用独立备注弹窗。

### 报销组

默认压缩为一行：报销组选择、组状态、管理入口。删除、拆分和查看组内发票进入“管理”菜单或报销信息 Tab，不长期占用详情首屏。

### 键盘操作

| 快捷键 | 动作 |
|---|---|
| `Ctrl+F` | 聚焦全局搜索 |
| `J` / `K` | 下一张 / 上一张发票 |
| `Ctrl+Enter` | 保存当前编辑区域 |
| `Alt+A` | 通过并下一张 |
| `Alt+I` | 忽略 |
| `Alt+E` | 标记异常 |
| `Esc` | 关闭浮层或取消当前临时操作 |

快捷键在文本输入控件中不得拦截正常字符输入。所有焦点必须可见，Tab 顺序遵循从列表、预览工具栏到详情表单和动作栏的视觉顺序。

快捷键优先级固定如下：

1. 模态对话框拥有最高优先级，主窗口快捷键全部暂停，只有对话框自身的 `Esc`、`Enter` 和 Tab 导航生效。
2. 单行或多行文本输入获得焦点时，`J`、`K` 和所有字母型单键快捷键暂停；`Ctrl+F`、`Ctrl+Enter` 和 `Esc` 继续按当前编辑区域定义执行。
3. 列表或非输入区域获得焦点时，所有主窗口快捷键生效。
4. 存在未保存编辑时，切换、忽略和异常快捷键必须先走保存/放弃/取消保护流程。

## 0.1.4 扫码上传设计

使用 760×560 的 `DialogShell`，分为左右两栏。

- 左栏：网络地址、二维码、上传链接、复制链接。
- 右栏：服务状态、上传批次、成功/重复/失败/入库数量、最近上传文件。
- 底栏：刷新状态、复制链接、停止服务或启动服务。

状态定义：

| 状态 | 表现 | 可用动作 |
|---|---|---|
| 启动中 | 加载提示，二维码占位 | 取消 |
| 运行中 | 显示二维码、地址和绿色状态 | 复制、刷新、停止 |
| 已停止 | 二维码遮罩 | 启动、关闭 |
| 网络不可用 | 错误说明 | 更换地址、重试 |
| 二维码过期 | 二维码遮罩 | 刷新二维码 |
| 上传中 | 显示批次进度 | 保持服务运行 |
| 部分失败 | 成功与失败数量分开 | 查看失败、继续上传 |

上传成功后发出结果对象，主窗口仅刷新受影响的统计与列表并选中新导入发票。切换公网/LAN 地址不得隐式旋转仍有效的 token；文件类型、批量上传、去重、软删除恢复和附件路径继续沿用现有业务规则。

## 0.1.5 设置中心设计

设置中心使用 1120×720 的模态对话框，左侧 180 px 设置导航，右侧为当前设置内容，底部 64 px 固定操作栏。

设置导航：邮箱集成、AI 模型、系统设置、数据与备份、关于。0.1.5 中 AI 模型仅保留现有配置入口，不展示 0.1.6 才有的功能中心。

底部左侧显示安全提示和恢复默认设置，右侧显示取消与保存并关闭。切换设置分类时保留未保存编辑；关闭存在未保存内容时提供保存、放弃、取消三种选择。

## 0.1.5 邮箱集成设计

### 邮箱账户页

顶部显示说明和“新增邮箱账户”。账户列表每行显示邮箱地址、服务商、协议、扫描范围、同步状态、最近同步和操作菜单。

编辑、启用、停用和删除必须按 `mailbox_key` 精确路由。不能禁用最后一个已启用邮箱。无账户时展示支持服务商、安全说明和新增动作，不显示空表格。

### 三步向导

尺寸 760×560，步骤固定为：

1. 选择邮箱：服务商、邮箱地址、协议、检索范围和同步频率。
2. 填写授权码：配置摘要、安全输入、保存状态和获取授权码说明。
3. 测试并保存：身份验证、IMAP 连接、附件读取、邮件识别和同步预览。

保存账号与编辑草稿是两个独立状态：

- 加载已保存账户后，不自动重写邮箱地址。
- 只有尚未保存且用户正在输入的草稿地址允许按服务商调整后缀。
- `config.email_accounts` 是主要数据源，旧配置只作为兼容回退。
- `mailbox_key` 只能继续绑定同一个已保存账户。
- Outlook 不回退到传统 IMAP 密码登录。
- 授权码不在日志、摘要或测试结果中显示。

第三步只在全部必需测试通过后允许保存。测试成功但没有发现发票邮件不是错误，显示“连接正常，当前范围未发现发票邮件”。

## 0.1.6 AI 模型中心设计

顶部状态区展示：已启用配置数、默认模型、上次检查时间和密钥安全状态。主体使用紧凑配置列表，不使用大面积营销式卡片。

每个配置显示配置名称、提供商、模型、用途、密钥状态、最近校验、启用状态和操作。界面只显示“有效、未配置、已失效、待验证”，不显示旧 Key 或任何密钥片段。

新增配置沿用三步 `WizardDialog`：基本信息、模型与密钥、确认并保存。保存前需要连接测试；识别能力测试是可选动作，不阻塞只用于分类之外的配置。

## 0.1.6 规则管理设计

规则管理只覆盖现有系统能够执行的规则，按购买方、销售方、金额和发票四类组织。每类由 `RuleSection` 展示规则名称、匹配条件、动作、启用状态和最近命中信息。

不存在后端执行能力的规则不加入界面。删除规则需要确认；停用规则可直接操作并提供短时撤销。规则编辑不引入脚本语言或复杂表达式构建器。

## 状态与反馈规范

| 状态 | 颜色 | 必需文字 |
|---|---|---|
| 待审核 | 橙色 | 待审核 |
| 已通过 | 绿色 | 已通过 |
| 已忽略 | 灰色 | 已忽略 |
| 异常 | 红色 | 异常 |
| 同步中 | 蓝色 | 同步中 |
| 未配置 | 橙色 | 未配置 |
| 已配置 | 绿色 | 已配置 |
| 已失效 | 红色 | 已失效 |
| 已修改 | 蓝色 | 已修改 |
| 已保存 | 绿色或中性 | 已保存 |

Toast 只用于无需用户决策的短时反馈。需要选择、可能丢失数据或不可逆的操作使用对话框。错误信息必须说明发生了什么、用户输入是否保留以及下一步动作。

## 架构边界

### 保留

- `InvoiceReviewApp` 继续负责主窗口编排和业务回调。
- `InvoiceDetailPanel` 继续通过 setter 接收展示数据，通过 `InvoiceDetailCallbacks` 发出业务意图。
- `PreviewMixin` 继续负责文档和 PDF 预览交互。
- `make_button`、`make_badge`、`build_action_cluster` 与 QSS `variant/class` 模式继续使用并扩展。
- `SettingsDialog`、`MobileUploadDialog`、现有 worker 和公开导出名称保持兼容。

### 收敛

- 从 `_on_table_selection_changed()` 中抽出发票展示状态组装和选择结果分发，避免继续加入页面逻辑。
- 预览文档选择状态与详情支持材料选择状态通过明确的 view state 同步，不互相直接改控件。
- 邮箱已保存账户身份与草稿编辑状态分开建模。
- 扫码上传完成信号升级为批次结果对象，但主窗口仍决定刷新策略。

### 禁止

- 通用组件直接访问数据库、配置文件或凭据。
- 详情面板直接执行数据库写入。
- UI 重构同时改变发票解析、去重、源文件处理或导出语义。
- 以重新命名控件为理由删除现有兼容导出或测试锁定的行为。

## 数据保护与兼容要求

- 本地导入不得移动或删除用户源文件。
- 已审核、已关联或用户手工修改的数据不得被后台回填清空。
- 长文件名可以截断显示，但不得在界面暴露绝对路径或敏感目录。
- 授权码和 API Key 继续使用本地安全存储，不写入日志、配置明文或界面摘要。
- 密钥安全状态只能显示“未配置、已安全保存、待验证、验证失败、已失效”枚举，不回显、掩码显示、推断或拼接任何密钥内容。
- 失败下载、手工处理、软删除恢复和重复文件语义保持不变。
- AI 关闭或失败时不得污染原有分类和识别结果。

## 模型与人工分工

低成本模型适合：组件清单、状态矩阵、文案候选、测试骨架、低风险样式迁移、验收记录和文档同步。

强模型适合：主窗口状态拆分、三栏同步、审核事务、邮箱身份和密钥边界、跨模块集成与最终代码审查。

人工必须按本设计的尺寸、颜色、布局和状态标准签署版本验收；任何隐私策略、不可逆操作或版本扩展都必须通过新的设计变更，不在实施阶段临时决定。

## 设计完成定义

本设计在满足以下条件后进入实施计划阶段：

- 用户确认三个版本范围和通用组件边界。
- 页面结构、尺寸、交互、状态、错误和键盘操作均有明确规则。
- 不存在未决占位、空壳页面或隐含的新业务能力。
- 每个验收目标都能对应到版本任务包。
- 实施计划按版本分别编写，0.1.4 完成并验收后才启动 0.1.5。
