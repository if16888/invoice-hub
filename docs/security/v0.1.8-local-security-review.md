# v0.1.8 local security hardening review

This is a source-level review record, not stable-release authorization or a claim
that all static-analysis warnings are vulnerabilities. Exact-SHA CI, frozen
package validation and physical-device acceptance remain separate gates.

## Security changes

- Require and lock urllib3 2.8.0 for the proxy TLS and streaming denial-of-service
  advisories. Use a shared defusedxml parser for untrusted invoice XML, rejecting
  DTDs, entities and external references independently of encoding; retain the
  2 MiB input limit.
- Make the AI HTTP wrapper enforce finite positive timeouts of at most 60 seconds,
  including calls that omit the timeout. Reject invalid or unbounded values
  before network access.
- Resolve Explorer, PowerShell and netsh inside the Windows directory returned by
  the operating-system API, rather than trusting PATH or WINDIR. Explorer is
  invoked with an argument list, no shell and a finite wait.
- Resolve local paths before invoking the system default application. This is
  an explicit user action, not an automatic attachment execution sandbox.
- Run mobile self-checks against the actual HTTP listener, without URL schemes,
  environment proxies or redirect following. Compare session tokens using
  constant-time comparison after checking input type and length.
- Surface credential-deletion and database-compensation errors without backend
  exception text. Report database-count failures as unavailable data, not as an
  empty database. Log manifest/evidence-preview failures without private paths.

## Static-warning disposition

No blanket exclusion or `nosec` directive was added. The remaining warnings
must remain visible; this review does not authorize a global rule suppression.

| Rule | Reviewed behavior | Disposition |
| --- | --- | --- |
| B608 | Dynamic SQL uses fixed clauses, generated `?` placeholders or allowlisted column names; record values remain bound parameters | No injection demonstrated; synthetic injection regression added |
| B104 | Default LAN listener binds all IPv4 interfaces; self-check maps the wildcard listener address to loopback | Intentional LAN behavior; retain token/expiry/upload limits and firewall guidance |
| B404/B603 | Diagnostics uses the current interpreter plus a repository-owned script; Explorer and firewall use trusted system executables and argument lists | No shell interpolation; do not add untrusted commands or scripts |
| B606 | Local file opening through the system default handler after explicit user action | Intentional local desktop capability; not a malware/content safety guarantee |
| B105/B107 | Design version identifier, credential-status UI strings, empty default token used for redaction | Not embedded credentials |
| B110/B112 | Primarily optional Qt callbacks, disconnected signals, cleanup during shutdown, browser fallbacks and malformed local-history entries | Existing best-effort behavior retained; do not change cleanup to unconditional raises solely to satisfy the scanner |

The exception-warning review identified higher-value cases addressed above.
Remaining broad exception handlers are not certified harmless under all future
changes: persistence, export validation and authorization paths must continue
failing closed, and follow-up changes should narrow exception classes where
backend/Qt compatibility allows it. A clean scanner count is not the acceptance
criterion.

## Release evidence recovery

The initial security fixes were pushed directly to master. Local preflight
success and dependency-graph submission do not satisfy exact-master CI
attestation: it requires a merged PR with a successful full CI run whose head
tree is identical to the merge tree.

A documentation-only follow-up PR must therefore run the full source, unit and
HCI gates against the complete tree containing these security fixes. This
verifies the complete product tree; it does not retroactively claim the original
code changes were introduced through a PR. Merge only after required checks
succeed, then confirm master attestation before dispatching a Windows pre-tag
audit from that exact master SHA. The previous Windows audit is historical
and cannot authorize binaries containing the new runtime dependencies or code.
No attestation bypass, relaxed gate, release tag or publication is part of this
recovery.

## Validation and limits

- Full local preflight: source/privacy/public-export/architecture gates, isolated
  unit shards, HCI acceptance and HCI oracle.
- Synthetic regression coverage: XML encodings and ZIP path; finite AI timeout;
  listener-only mobile self-check under poisoned proxy/URL settings; no redirect
  following; token validation; system executable resolution independent of
  PATH/WINDIR; SQL value binding and column allowlisting; private-safe credential
  failure logging.
- Locked dependency audit: runtime, desktop and build entries queried against
  the advisory service, with no package skipped. This is a known-vulnerability
  check, not a proof of dependency safety or independently resolved closure.
- Source privacy and limited tracked-text secret-pattern scanning do not replace
  git-history scanning, binary inspection or private-data review.
- This local work does not verify rebuilt Windows packages, Android devices,
  mailbox end-to-end behavior or physical DPI/upgrade acceptance. Runtime changes
  require a new candidate SHA and rebuilt audited artifacts.
