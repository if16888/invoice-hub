## Security impact validation

Invoice Hub accepts PDF files through local import, mailbox import, and the
mobile HTTP upload path. The application then reaches `pdfplumber` from
`scripts/invoice_fetch/invoice_parser.py` and from the simple extraction helper
in `scripts/invoice_fetch/__main__.py`; `pdfplumber` delegates PDF parsing to
`pdfminer.six`.

The installed `pdfminer.six` source was inspected before changing dependency
files. Its CMap loader uses the secure compressed JSON data path and validates
that resolved files stay under the intended CMap directory; the old pickle
loader is absent. The current installed version is already `20260107`, which
is above the `20251230` fixed floor documented by the upstream advisories:

- CVE-2025-64512 / GHSA-wf5f-4jwr-ppcp: <https://github.com/pdfminer/pdfminer.six/security/advisories/GHSA-wf5f-4jwr-ppcp>
- CVE-2025-70559 / GHSA-f83h-ghpp-7wcc: <https://github.com/advisories/GHSA-f83h-ghpp-7wcc>

The product and installed `pdfminer.six` source contain no
`pkcs7_decrypt_der`, `pkcs7_decrypt_pem`, `pkcs7_decrypt_smime`,
`load_der_pkcs7`, or `load_pem_pkcs7` call. The PDF encryption path uses
`cryptography.hazmat.primitives.ciphers.Cipher` with AES/CBC and the legacy
RC4 helper. Therefore cryptography alert #45's required PKCS#7 EnvelopedData
decryption API is not reachable from the product PDF path. The dependency is
still upgraded to the patched `50.0.0` floor for maintenance and provenance.

## Remediation target

Production and Windows release installation must use committed lock files, not
floating `requirements.txt` resolution. Runtime, desktop, and build inputs
are kept as separate locked inputs and are installed together by CI/release.

The minimum security floors are:

- `pdfminer.six >= 20251230`;
- `Pillow >= 12.3.0`;
- `cryptography >= 50.0.0`.

## Compatibility validation

Only synthetic/public-safe PDF fixtures were used. No user invoice, mailbox,
credential, or production path was copied into the evidence.

- Ordinary one-page PDF: opened and extracted successfully.
- Multi-page PDF: opened with two pages and extracted successfully.
- Chinese/CMap path: `UniGB-UCS2-H` loaded through the JSON CMap data path.
- Broken PDF and HTML masquerading as PDF: failed closed as parse failures
  without an application crash.
- Encrypted PDF: the existing product parser does not expose a password or
  encrypted-input contract, so this is recorded as not applicable rather than
  claimed as newly supported. No encrypted-PDF behavior was changed.

The cryptography advisory's required PKCS#7 EnvelopedData auto-decryption API
is absent from both the product and the reachable PDF parser path. This keeps
the alert classified as `NOT_ACTIONABLE` for reachability, while the dependency
is nevertheless pinned to the patched `50.0.0` floor:
<https://github.com/advisories/GHSA-g6cj-pr64-35w5>.
