## Product Reachability Model

The product accepts email attachments and downloaded files, validates their basic
container signature, and stores them under the local runtime directory. PDF files are
then opened by `pdfplumber` for text extraction, limited to the first two pages. The
relevant static paths are:

- `scripts/invoice_fetch/attachment_handler.py`: attachment classification, magic
  checks, and file writes; no Pillow decode is performed.
- `scripts/invoice_fetch/invoice_parser.py`: lazy `pdfplumber` import and PDF text
  extraction.
- `scripts/invoice_fetch/__main__.py`: a second `pdfplumber` text extraction helper.
- `scripts/invoice_fetch/gui/mobile_upload_dialog.py` and
  `scripts/invoice_fetch/gui/mobile_upload_session.py`: `qrcode.make(url)` followed
  by PNG serialization. The URL is generated by the application; these paths do not
  parse an attacker-supplied image.
- `packaging/invoice_hub_windows.spec`: packages `PIL`, `PIL.Image`, `qrcode`, and
  `cryptography` as hidden imports, so package presence is real even where the named
  vulnerable API is not statically reached.

The repository contains no direct import of `cryptography`, no PKCS#7 decrypt call,
and no direct Pillow call to the affected image, font, EPS, TGA, JPEG2000, PDF, CMS,
filter, crop, paste, or Windows viewer entry points listed in the advisories.

### Advisory Summary Index

- **#45:** PKCS#7 EnvelopedData decryption exposes a Bleichenbacher oracle through distinguishable errors and timing.
- **#31:** Controlled heap out-of-bounds write in `ImageCmsTransform.apply()` via output mode mismatch.
- **#30:** JPEG2000 tiled decode retains a growing scratch buffer and can cause denial of service.
- **#29:** Decompression-bomb denial of service via `PdfParser.PdfStream.decode()`.
- **#28:** Heap out-of-bounds write in `Image.paste()` / `Image.crop()` via signed coordinate overflow.
- **#27:** TGA RLE encoder can serialize adjacent heap data into generated images.
- **#26:** Heap out-of-bounds write in `ImageFilter.RankFilter` via integer overflow in `ImagingExpand`.
- **#25:** Windows viewer command injection through an unescaped shell path.
- **#24:** `GdImageFile._open()` accepts image dimensions without decompression-bomb checking.
- **#23:** `BdfFontFile` bypasses decompression-bomb checking during font loading.
- **#22:** `FontFile.compile()` creates an unchecked combined bitmap during font processing.
- **#21:** `PcfFontFile._load_bitmaps()` bypasses decompression-bomb checking.
- **#20:** Attacker-controlled row stride can cause an out-of-bounds read on Pillow's mmap path.
- **#19:** Negative EPS `%%BeginBinary` byte count can cause an infinite-loop denial of service.

### Why the Pillow Results Are Not `CONFIRMED`

The package is present in the desktop dependency graph, but package presence alone is
not a reachable exploit path. The only repository Pillow-related operation is the
`qrcode.make(url)` output path, and the application does not accept an image, font,
PDF, EPS, TGA, JPEG2000, or viewer command as input to Pillow. The attachment handler
stores image payloads after signature checks and leaves later image processing to
manual/product paths outside this alert scope. This is positive evidence for the
review-time source tree, not a dismissal of the upstream advisories.

## Top Three Priorities

1. **P1 / alert #45:** establish whether `pdfminer-six` can reach the vulnerable
   PKCS#7 decryption APIs when processing an untrusted PDF; until then this is not
   safe to close as not actionable.
2. **P1 / dependency source of truth:** decide whether `requirements.lock.txt` is the
   release source. At review time, CI/release installed unpinned requirements, so the shipped
   `InvoiceHub.exe` version is not reproducible from the committed lock file.
3. **P2 maintenance / alerts #19-#31:** update Pillow to `12.3.0` or later after
   compatibility review, even though the review-time source did not reach the named
   vulnerable APIs. The update reduces future exposure if image handling expands.
