# Invoice Hub v0.1.8 — Release notes

> Release line: **v0.1.8.** Live publication status is authoritative on the GitHub Releases page.
> This source snapshot intentionally does not hard-code whether an official tag,
> GitHub Release, or public asset currently exists.

## Source boundary

- A v0.1.8 release is authorized only from the exact `master` SHA recorded by
  the Final Release Readiness Audit.
- Invoice Hub v0.1.7 is the previous published stable line for this source
  release line; its historical annotated tag and release notes remain intact.
- Earlier v0.1.8 candidates are historical evidence, not release authority.
- `master@0e7b46b4ca7bf19b742d12fd06ff5d6640fc4ed8` is a historical audit
  candidate; it was superseded after the audit found a release-infrastructure
  gap: the official Windows workflow could not produce pre-tag audit evidence
  and did not smoke-test the real generated installer.
- `v0.1.8-rc2 @ 6f178a0213d6e8a1e0174743d14c8b9385e07ca1` is a historical
  prerelease candidate and does not include PR #155.
- `master@8442f4ef318353b9625cbe59289cc773d5b2c4d8` is the source baseline that
  closed the RC3 build-identity and zero-byte-original gaps. Later stable
  preparation may supersede it only through the exact-master release gates.
- No architecture-retirement work is part of release finalization; the frozen
  architecture baseline remains 14 / 4.

## What's changed

- Local import cancellation stops at safe top-level source boundaries while
  preserving completed results and keeping the application responsive.
- Mailbox and invoice redownload work runs outside the GUI thread with explicit
  lifecycle and shutdown ownership.
- Deduplication avoids weak seller-plus-amount suppression when invoice identity
  is not strong enough to prove a duplicate.
- Startup release evidence requires a completed Qt main-window first-paint event
  and fails closed on missing, legacy, zero-paint, nonzero-exit, or inconsistent
  evidence.
- Review workbench, export safety, SQLite migration/backup, privacy gates, and
  release metadata checks are covered by the Windows CI lanes.
- Complete claim-package export now requires each included invoice original to
  be a readable, non-empty regular file and verifies the copied result.
  Missing, inaccessible, unreadable, zero-byte, or copy-failed originals block
  the export instead of producing an incomplete reimbursement package.

## Final release validation contract

A final GO requires both of these to pass on the same exact `master` candidate:

1. Exact-master CI: source gates, all three unit-test shards, and HCI acceptance.
2. A pre-tag `Windows Build & Release` audit dispatched from `master`. The
   workflow event SHA is the candidate identity and must equal checked-out HEAD
   and `origin/master` both before the build and immediately before audit-package
   evidence is uploaded. The audit must verify the portable executable startup
   gate, bundled-payload hygiene, Inno Setup build, historical installer
   ownership recovery, and a real generated-installer `install -> startup ->
   uninstall` smoke test.

Stable Windows publication additionally requires both the frozen portable
`InvoiceHub.exe` and the generated installer to carry a valid Authenticode
signature from the configured publisher. Stable signing is fail-closed: missing
signing configuration, an invalid/mismatched signer, or a missing trusted
timestamp blocks publication. RC/pre-release and pre-tag audit artifacts may be
unsigned while publisher signing is being provisioned; those builds can trigger
SmartScreen unknown-publisher or low-reputation warnings. SHA256 remains an
artifact-integrity check and does not replace publisher identity verification.

The pre-tag audit uploads ephemeral GitHub Actions evidence only. It must not
create a release tag, GitHub Release, or public release assets. Tag-based
publication remains a separate action after GO and requires an annotated tag.
If a local `v0.1.8` tag is present, the release-metadata gate rejects it unless
it is annotated.

Static repository text records the release line and historical stable lineage;
it does not encode mutable live publication state. This keeps the same source
snapshot truthful before and after publication while GitHub Releases remains
the live authority.

Native GUI geometry remains a known host-specific, explicitly non-gating CI
lane. It must not be misreported as a passing release gate.

## Known limitations

- Parsing results still require human review before reimbursement submission.
- OFD and other unsupported or weakly parsed documents can require manual
  review or supplementation.
- The Windows package carries the Playwright driver/runtime integration but not
  a bundled Chromium browser; browser-assisted download paths depend on a
  usable browser in the local environment or the existing fallback behavior.
- The application remains local-first and does not provide cloud sync or direct
  enterprise expense-platform submission.
- Prerelease, unsigned, or newly signed low-reputation Windows builds can still
  trigger SmartScreen warnings. Stable publication requires a valid timestamped
  Authenticode publisher signature, but SmartScreen reputation can still take
  time to accumulate.
