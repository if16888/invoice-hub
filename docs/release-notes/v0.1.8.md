# Invoice Hub v0.1.8 — Release notes

> Publication state at this source snapshot: **Unreleased.** This file does not
> claim that v0.1.8 has already been published. Live publication status is
> authoritative on the GitHub Releases page.

## Source boundary

- A v0.1.8 release is authorized only from the exact `master` SHA recorded by
  the Final Release Readiness Audit.
- Earlier v0.1.8 candidates are historical evidence, not release authority.
- `master@0e7b46b4ca7bf19b742d12fd06ff5d6640fc4ed8` entered the final audit after
  the startup-probe truthfulness blocker was closed, then was superseded only
  because the audit found a release-infrastructure gap: the official Windows
  workflow could not produce pre-tag audit evidence and did not smoke-test the
  real generated installer.
- No architecture-retirement work is part of that release-infrastructure
  closure; the frozen architecture baseline remains 14 / 4.

## What's changed

- Local import cancellation stops at safe top-level source boundaries while
  preserving completed results and keeping the application responsive.
- Mailbox and invoice redownload work runs outside the GUI thread with explicit
  lifecycle and shutdown ownership.
- Deduplication avoids weak seller-plus-amount suppression when invoice identity
  is not strong enough to prove a duplicate.
- Startup release evidence now requires a completed Qt main-window first-paint
  event and fails closed on missing, legacy, zero-paint, nonzero-exit, or
  inconsistent evidence.
- Review workbench, export safety, SQLite migration/backup, privacy gates, and
  release metadata checks are covered by the Windows CI lanes.

## Final release validation contract

A final GO requires both of these to pass on the same exact `master` candidate:

1. Exact-master CI: source gates, all three unit-test shards, and HCI acceptance.
2. A manually dispatched pre-tag Windows release audit using the full
   `candidate_sha`. The audit build must verify the portable executable startup
   gate, bundled-payload hygiene, Inno Setup build, historical installer
   ownership recovery, and a real generated-installer `install -> startup ->
   uninstall` smoke test.

The pre-tag audit uploads ephemeral GitHub Actions evidence only. It must not
create a `v0.1.8` tag, GitHub Release, or public release assets. Tag-based
publication remains a separate action after GO and requires an annotated tag.

Native GUI geometry remains a known host-specific, explicitly non-gating CI
lane. It must not be misreported as a passing release gate.

## Known limitations

- Parsing results still require human review before reimbursement submission.
- OFD and other unsupported or weakly parsed documents can require manual
  review or supplementation.
- The Windows package carries the Playwright driver/runtime integration but not
  a bundled Chromium browser; browser-assisted download paths depend on a
  usable browser in the local environment or the existing fallback behavior.
- The application remains local-first and does not provide cloud sync or direct
  enterprise expense-platform submission.
- Unsigned or low-reputation Windows builds can still trigger SmartScreen or
  Unknown Publisher prompts.
