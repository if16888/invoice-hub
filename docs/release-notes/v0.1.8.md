# Invoice Hub v0.1.8 — Release notes

> Release line: **v0.1.8.** Live publication status is authoritative on the GitHub Releases page.
> This source snapshot records the release contract and product changes, not a mutable publication-state claim.

## Source boundary

- A v0.1.8 release is authorized only from the exact master SHA recorded by the Final Release Readiness Audit.
- Invoice Hub v0.1.7 remains the previous published stable line for this source release line.
- Earlier v0.1.8 RCs and audit candidates are historical evidence only; they are not release authority.
- Publication happens only after final GO and requires the repository's annotated-tag release path.
- Release finalization is stabilization work. It does not expand the product scope or restart architecture-retirement work.

## What changed

### Intake and review correctness

- Local ZIP import now reconciles supported members and fails closed on archive safety limits instead of silently producing partial results.
- Import-result review actions stay bound to the intended batch, while normal review can continue beyond the first 50 rows.
- Continuous-review coverage includes quarter-scale data so row selection does not wrap back to the first page while later rows remain.
- Mail scanning, invoice re-download and other long-running operations use bounded background work and cooperative shutdown ownership instead of blocking the GUI thread.

### Export integrity

- Claim export requires every included invoice original to be a readable, non-empty regular file.
- Required supplemental evidence is validated with the same availability rule before export side effects begin.
- Non-finite amounts are rejected, claim totals are revalidated, and Excel monetary cells are written as numeric values with two-decimal formatting.
- Claim-package generation runs in a background worker with progress feedback and safe application-shutdown handling.

### Desktop usability and lifecycle

- First-run example configuration is no longer promoted into live company or mailbox configuration.
- Evidence states distinguish available, unavailable, required-but-missing, optional-not-added and not-required cases.
- Collapsed navigation remains keyboard reachable. Background complete backup/restore includes database records and associated originals/evidence; database-only backup remains available with its scope explained.
- Invoice notes persist during review navigation, with failed writes retained for retry. Partial drafts can be saved while approval/export still validates required fields.
- Import-source cards adapt to available width; empty export states offer group creation and invoice selection.
- PDF preview replacement keeps the current document attached until a ready replacement exists, avoiding transient null-document attachment.
- Regression coverage captures Qt messages during repeated real QtPdf document switches and rejects the known QPdfLinkModel/null-document and invalid font-size warnings.
- Settings status presentation uses semantic Design v1 states instead of inline font-color markup, and unreachable legacy preview-toolbar source has been removed.

### External input and privacy boundaries

- AI classification sends only fixed classification keywords and sender types. OpenAI and DeepSeek requests now use the endpoint matching the selected credential/profile.
- Complete and database-only restores reject unexpected SQLite triggers before path updates or migrations; legacy schema migration remains supported.
- PDF parsing uses a bounded, terminable child process and an atomic result file. Mobile uploads enforce absolute header/body deadlines and bounded request resources.

### Public documentation

- README is reorganized around the actual collect → review → group → export workflow.
- Documentation now has a dedicated index and clearer separation between user guidance, privacy/security, release evidence and architecture records.
- Product visuals are privacy-safe, diffable SVG illustrations built from synthetic content rather than embedded raster/base64 screenshots.
- Stale root-level design patches, local-path QA notes and obsolete test-audit artifacts have been removed.

## Final release validation contract

A final GO requires all of the following on the same exact master candidate:

1. Exact-master CI: source/privacy/architecture gates, all required unit-test shards, and HCI acceptance.
2. A pre-tag **Windows Build & Release** audit from master. The workflow event SHA, checked-out HEAD and origin/master must identify the same candidate before evidence is accepted.
3. Release-specific Windows checks: frozen build, startup threshold, embedded version identity, payload hygiene, Inno Setup build, installer ownership recovery, real install → startup → uninstall, and SHA256 artifacts.
4. Controlled physical-Windows acceptance: clean install, upgrade from the previous stable release, restart persistence, and 100% / 125% / 150% DPI review.

The pre-tag audit uploads ephemeral Actions evidence only. It must not create a release tag, GitHub Release, or public release assets. Tag-based publication is a separate action after GO.

Static repository text records the release line and historical stable lineage; it does not encode mutable live publication state. GitHub Releases remains the live authority.

Hosted native-GUI geometry may remain a non-gating diagnostic when the hosted desktop cannot satisfy the physical geometry contract. That does not waive the physical-Windows release acceptance above.

## Known limitations

- Parsing results still require human review before reimbursement submission.
- OFD, images and scanned documents can require manual completion.
- Browser-assisted invoice download can be affected by login, CAPTCHA, expiring links or provider-page changes.
- Mobile upload requires a reachable local network between the phone and desktop; firewall and network-isolation policies can block it.
- The Windows package carries Playwright driver/runtime integration but not a bundled Chromium browser.
- The application remains local-first and does not provide cloud sync, enterprise approval, automatic payment or direct expense-platform submission.
- Unsigned or low-reputation Windows builds can trigger SmartScreen or Unknown Publisher prompts.
