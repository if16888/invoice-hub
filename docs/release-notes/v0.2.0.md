# Invoice Hub v0.2.0 — Release notes

> Release line: **v0.2.0.** Live publication status is authoritative on the GitHub Releases page.
> This source snapshot records the release contract and product changes, not a mutable publication-state claim.

## Source boundary

- A v0.2.0 release is authorized only from the exact master SHA recorded by the pre-tag Windows Build & Release audit.
- Invoice Hub v0.1.8 remains the previous published stable line for this source release line.
- Pre-tag audit candidates are historical evidence only; they are not release authority.
- Publication happens only after final GO and requires the repository's annotated-tag release path.
- Release finalization is stabilization work. It does not expand the product scope.

## What changed since v0.1.8

### 报销组、事由与导出

- 报销事由（Reason）成为组级一等字段，贯穿报销组填报、台账明细、自动封面和文件命名。
- 导出自动生成 A4 报销单封面与费用明细；金额与票数使用 Decimal/计数结果写成静态值，支持自定义文件名模板。
- 报销组导出包包含 `reimbursement.xlsx`、`manifest.json` 与原件副本；清单记录每个文件的 SHA-256，用于发现缺失或被替换的文件。
- 导出前逐张校验原件与补充材料是可读的非空文件；非有限金额拒绝导出。
- 导出使用快照摘要与全量成员复核，阻断导出期间的成员增删改（TOCTOU）；财务字段与事由在导出锁定后不可绕过修改。
- 跨报销组并发归属在写锁内复核，竞争写入只有一方成功；导出历史与核销状态持久化。

### 审核、查重与财税字段

- 无票号票据（行程单/打车票）软指纹复核：销售方、有效日期、Decimal 金额和币种弱匹配，由人工确认，不覆盖审核状态。
- 批量审核支持全选、通过所选与通过全部筛选结果（带二次确认）；连续审核并入统一批量入口；审核表格默认展示「报销组」列。
- 购买方税号与证件类型、税前金额、税额、税率、发票代码可编辑并持久化；价税平衡按 Decimal 校验，缺失数据不视为零。
- 报销核销状态机、单票 `Ctrl+G` 快捷归组、销售方分类偏好记忆。

### 采集、导入与桌面体验

- 桌面拖拽导入、本地 ZIP 安全解包、手机局域网上传与 AP 隔离诊断指引。
- 邮箱扫描与发票重下载、供应商分类偏好学习、导入结果按批次复核。
- 设置中心按「常用 / 高级」分级；空库只保留三步上手引导；审核页提供单引导空态、报销组列与统一批量菜单。
- 右侧详情面板支持拖拽、双击与快捷键折叠；窄屏自动收起并在恢复时保留用户宽度。

### 安全与可靠性

- 浏览器下载使用本地过滤代理：在建立网络连接前拒绝内网、回环与链路本地目标，重定向目标零请求到达；Chromium 显式启用沙箱。
- 新版数据库在版本闸门前置时保持文件字节不变；写入序列化、备份/恢复前后校验与安全回滚覆盖数据库及关联原件。
- 真实浏览器 SSRF 回归纳入 PR 必过 CI 步骤，并保留发布前的实机复跑要求。
- GUI 几何预检在宿主 1024×768 上判定环境不适用并干净跳过；实体 Windows 显示环境验收仍是发布门槛。

## Final release validation contract

A final GO requires all of the following on the same exact master candidate:

1. Exact-master CI: source/privacy/architecture gates, all required unit-test shards, and HCI acceptance.
2. A pre-tag **Windows Build & Release** audit from master. The workflow event SHA, checked-out HEAD and origin/master must identify the same candidate before evidence is accepted.
3. Release-specific Windows checks: frozen build, startup threshold, embedded version identity, payload hygiene, Inno Setup build, installer ownership recovery, real install → startup → uninstall, and SHA256 artifacts.
4. Controlled physical-Windows acceptance: clean install, upgrade from v0.1.8, restart persistence, local import/review/export, and 100% / 125% / 150% DPI review.

The pre-tag audit uploads ephemeral Actions evidence only. It must not create a release tag, GitHub Release, or public release assets. Tag-based publication is a separate action after GO.

Static repository text records the release line and historical stable lineage; it does not encode mutable live publication state. GitHub Releases remains the live authority.

Hosted native-GUI geometry may remain a non-gating diagnostic when the hosted desktop cannot satisfy the physical geometry contract. That does not waive the physical-Windows release acceptance above.

## Known limitations

- Parsing results still require human review before reimbursement submission.
- OFD, images and scanned documents can require manual completion.
- Browser-assisted invoice download can be affected by login, CAPTCHA, expiring links or provider-page changes.
- Mobile upload requires a reachable local network between the phone and desktop; firewall and network-isolation policies can block it.
- The Windows package carries Playwright driver/runtime integration but not a bundled Chromium browser; Microsoft Edge is used when Chrome is unavailable.
- The review list keeps a designed fixed height (276px); the user-adjustable pane is the right-side detail panel. Displays below 1366×768 can compress the list further and are not a validation target.
- Unsigned or low-reputation Windows builds can trigger SmartScreen or Unknown Publisher prompts.
- The application remains local-first and does not provide cloud sync, enterprise approval, automatic payment or direct expense-platform submission.
