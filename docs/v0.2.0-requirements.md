# Invoice Hub v0.2.0 需求与技术规范全景归档

> **文档性质**：v0.2.0 统合规划与落地规格书（Unified Requirements & Technical Specification）
> **归档基准**：继承自前序双角色合规审查（B-1 ~ B-7）与打工人报销全链路体验审查（R-1 ~ R-7）
> **状态定位**：v0.1.8 Feature Freeze 期间归档备忘，待 v0.1.8 实体机验收发布后正式开辟 v0.2.0 分支实施

## 一、版本使命与核心主题

### 1.1 从“发票整理箱”跨越为“打工人报销生产力工具”
v0.1.8 筑牢了**“本地优先 + Windows 凭据管理器 + 绝不上云”**的数据安全底线，并在 PR #178 中闭环了“跨报销组重复拦截”与“OFD 原件保留”。

**v0.2.0 的核心主题**：
> **「事由驱动 · 智能防漏 · 一键成单」**
1. **事由一等公民**：将报销事由贯穿“报销组填报 ➔ 台账明细 ➔ 自动封面 ➔ 文件命名”全链路，解决财务报销的核心要素断点。
2. **查重无死角**：引入无票号票据（行程单/打车票）软指纹查重，杜绝重拍/重导导致的虚假重报。
3. **极速审核交付**：批量审核、商家分类偏好记忆、审核面板自适应折叠，将 100+ 张票据整理耗时从小时级压缩至分钟级。
4. **财务级数据闭环**：落地税号持久化、价税分离、1:N 共享凭据、状态机追溯，消灭财务退单。

## 三、Epic 深度规格设计

### Epic 1: 事由（Reason）一等公民化与导出闭环（E-01, E-02）

#### 1. 业务上下文与痛点
- 财务退单高频原因：“发票明细杂乱，不知道哪笔钱属于哪个项目/出差”。
- 现状：报销组只有 `name`，单票只有 `note`。员工只能在数十张票上挨个敲“出差北京”。

#### 2. 数据模型改造（Migration V9）
```sql
ALTER TABLE claim_groups ADD COLUMN reason_category TEXT DEFAULT '差旅出差'; -- 预设分类：差旅出差/商务招待/团队建设/办公采购/其他
ALTER TABLE claim_groups ADD COLUMN reason_detail TEXT DEFAULT '';          -- 详细说明，如：8月上海华东客户拜访
ALTER TABLE claim_groups ADD COLUMN applicant_name TEXT DEFAULT '';         -- 报销人姓名
ALTER TABLE claim_groups ADD COLUMN department TEXT DEFAULT '';             -- 报销人部门

ALTER TABLE invoices ADD COLUMN custom_reason TEXT DEFAULT '';              -- 允许单票覆盖/微调事由（为空时继承组事由）
```

#### 3. Excel 导出改造
1. **新增【报销封面】Sheet（Summary Cover）**：
   - 样式精美、居中排版，预留 A4 打印边距；
   - 核心要素：报销单号、报销人、所在部门、事由类别、事由详细说明、报销起止日期；
   - 费用统计：单据总张数、价税合计小写（`¥ 3,450.00`）、价税合计大写（`叁仟肆佰伍拾元整`）；
   - 财务审批栏：`[ 报销人: _________ ]  [ 部门主管: _________ ]  [ 财务审核: _________ ]`。
2. **【发票明细】Sheet 增加第 21 列**：
   - 表头：`报销事由`；
   - 取值规则：`invoice.custom_reason or claim.reason_detail or claim.reason_category`。
3. **导出文件命名模板引擎**：
   - 支持设置模板格式：`{YYYYMM}_{部门}_{姓名}_{事由}_{金额合计}.xlsx`；
   - 默认生成示例：`202610_销售部_张三_上海出差_3450.00.xlsx`。

### Epic 2: 无票号票据软指纹查重与待人工复核队列（E-03）

#### 1. 业务上下文与痛点
- 出租车发票、定额发票、航空客票行程单往往没有标准的 20 位数电发票号码；
- 员工微信重新导出或手机重新拍照时，文件 MD5 散列必然变化，导致查重防线击穿。

#### 2. 软指纹生成算法
针对 `invoice_number` 为空或长度小于 8 位的票据：
$$\text{SoftHash} = \text{SHA256}(\text{Clean}(\text{seller\_name}) + "|" + \text{Format}(\text{invoice\_date}) + "|" + \text{Round}(\text{total\_amount}, 2))$$

#### 3. 拦截与流转逻辑
```
导入票据
   │
   ├─ 有标准票号 ──> 命中精确 UNIQUE(number, code) ──> 硬拦截重复
   │
   └─ 无标准票号 ──> 计算 SoftHash
                       │
                       ├─ 未命中 ──> 正常入库 (status = 'pending')
                       │
                       └─ 命中已存在记录 ──> 标记 status = 'duplicate_suspect'
                                               │
                                               ▼
                                      进「待人工复核」侧边栏筛选
                                      (高亮提示: 发现疑似同销售方/日期/金额票据)
```
- **原则**：不盲目静默丢弃（避免误伤同天多次打车），但绝不直接放行，强制人工勾选确认。

### Epic 3: 批量审核与销售方偏好记忆（E-04, E-05）

#### 1. 表格批量审核
- 列表支持多选（`Shift+点击`、`Ctrl+点击` 或全选勾选框）；
- 底部悬浮/右键菜单提供：**“批量标记为已审核 (N 张)”**；
- **安全门槛**：若勾选列表中含有“购买方异常”、“缺证明材料”或“疑似重复”的发票，弹窗提示并默认剔除异常项，仅对其余合规发票执行批量通过。

#### 2. 销售方分类偏好学习（SQLite 记忆表）
```sql
CREATE TABLE IF NOT EXISTS seller_category_preferences (
    seller_name TEXT PRIMARY KEY,
    preferred_category TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
```
- 当用户手动在详情面板修改发票分类时（如将“滴滴出行”从“其他”改为“交通费”），自动更新该表；
- 后续导入新发票时，规则引擎优先检索偏好表，实现“一次纠正，终身免修”。

---

### Epic 4: 凭据脱解与 1:N 共享证明材料（B-05）

#### 1. 解除 `mail_uid` 刚性约束
- 彻底废除 `db.py:link_evidence_to_invoice` 中对 `mail_uid` 的同源强校验；
- 只要证明材料在库中（本地导入、手机上传均可），即可通过 UI 自由建立关联。

#### 2. 建立多对多关系表
```sql
CREATE TABLE IF NOT EXISTS invoice_evidence_relations (
    invoice_id INTEGER NOT NULL,
    evidence_id INTEGER NOT NULL,
    created_at TEXT NOT NULL,
    PRIMARY KEY (invoice_id, evidence_id),
    FOREIGN KEY (invoice_id) REFERENCES invoices(id) ON DELETE CASCADE,
    FOREIGN KEY (evidence_id) REFERENCES invoices(id) ON DELETE CASCADE
);
```
- **业务场景覆盖**：1 张 800 元的高铁/滴滴汇总水单，可同时关联给当次出差的 4 张发票；导出打包时自动将该水单文件分发引用到对应目录或 Manifest 中。

### Epic 5: 界面交互、网络体验与架构收敛（E-06, E-07, A-01）

#### 1. 审核面板弹性伸缩与折叠
- 主布局改用标准 `QSplitter`，记录用户拖拽宽度至 `QSettings`；
- 分割栏中置微型折叠按钮 `[ < ]` / `[ > ]`，支持快捷键 `Ctrl+B` 一键隐藏右侧 420px 审核面板，使左侧票面预览区占满 100% 窗口。

#### 2. 手机上传 AP 隔离网络诊断
- 手机端上传网页在加载时主动 ping 电脑端探针接口；
- 若 3 秒内未收到握手响应，手机端顶部悬浮黄色排查卡片：
  > ⚠️ 无法连接电脑？公司 Wi-Fi 可能开启了 **AP 隔离**。
  > **解决建议**：① 手机开启个人热点，电脑连接手机热点后重新扫码；② 或在微信中将发票“保存到手机”，通过微信文件传输助手传到电脑后直接拖入软件。

#### 3. 架构维护债封顶（Freeze Patch-Modules）
- 现有 58 个 GUI 文件中带 `*_fixes.py`、`*_baseline.py`、`*_closure.py` 等命名模块正式打上 `@deprecated` 注释，进入只读维护期；
- v0.2.0 所有新界面代码强制建立在 `src/gui/components/` 结构下，推行标准 MVVM / Controller 架构模式。

## 五、验收基准与合规守护

v0.2.0 在推进全部生产力功能的同时，坚守以下不变承诺：
1. **本地优先原则不妥协**：不引入任何第三方强制公网云依赖，敏感凭据全量锁定于 Windows Credential Manager。
2. **启动性能底线**：新增特性不得劣化冷启动性能，便携版冷启必须维持在 $\le 5000\text{ ms}$，安装版启动维持在 $\le 2000\text{ ms}$。
3. **数据库平滑迁移**：Migration V9 必须向下兼容现有 v0.1.8 的生产数据库，提供自动备份与回滚机制。
4. **CI 门禁 100% 覆盖**：每个 Epic 均须配套端到端自动化测试与 HCI 验收用例。
