## Refresh ownership implemented

The completion path now has one explicit owner for each responsibility:

```text
batch completion
  -> record activity/state
  -> install latest review scope and TO_REVIEW filter
  -> one authoritative _load_invoices()
  -> load claims
  -> mark hidden summary pages dirty
  -> hand off to Review/Imports
  -> schedule paint
```

- `_prepare_import_activity_review()` installs the latest live review IDs,
  restored/duplicate metadata, and `TO_REVIEW` filter before the list load.
- `_load_invoices()` is owned by the completion caller and is executed once
  per authoritative mobile batch. `_open_import_activity_review()` is now a
  handoff helper; it does not perform an implicit second list load.
- Review selection/scope remains the latest batch only. A/B batches replace
  the prior scope, and the live remaining-review count is still computed from
  the database.
- `overview_dirty`, `imports_dirty`, and `settings_dirty` are set for hidden
  summary pages. The page refreshes once when that page is opened and clears
  its flag. The target Review/Imports handoff owns its visible refresh.
- Local import now updates the list/visible page and schedules the paint
  before showing its existing completion message. The message was retained.
- The settings page is included in performance surface visibility mapping so
  visible/invisible measurements are not misclassified.

## Automated semantic gates

The completion regression set covers:

- one-new mobile completion has exactly one authoritative list load;
- mixed and consecutive A/B mobile batches each load once;
- latest review scope replaces the previous scope;
- duplicate outcomes and review identity remain intact;
- hidden summary pages do not refresh during Review handoff and refresh once
  when opened;
- local import data is visible in the list before the completion dialog is
  invoked;
- existing import/review identity, duplicate, selection, remaining-count,
  and mobile lifecycle contracts remain covered by the targeted suites.
